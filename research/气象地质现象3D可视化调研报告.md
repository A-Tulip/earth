## 一、总体技术选型

### 1.1 三类核心渲染手段对比

| 手段 | 适用现象 | 代表 Three.js API | 优点 | 局限 |
|---|---|---|---|---|
| **粒子系统**（Points / GPUParticleSystem） | 风、洋流、气团运动、降水 | `THREE.Points` + `BufferGeometry` + 顶点着色器 | 直观表现"流动"，万级粒子 60fps | 不表现体积，单层平面感 |
| **自定义 Shader**（ShaderMaterial / RawShaderMaterial） | 锋面坡度云系、体积云、分层设色、流场 | `THREE.ShaderMaterial{uniforms, vertexShader, fragmentShader}` | 可控性最强，可实现体积/噪声/光照 | GLSL 门槛高，调试难 |
| **几何体 + 动画**（Mesh / Morph / SkinnedMesh） | 板块运动、河流地貌演变、地形 | `BufferGeometry` 顶点位移 / `MorphTargets` | 结构清晰，易交互 | 动态流体效果弱 |

> **关键判断**：锋面云系、气旋流场、洋流这三类"动态流体现象"必须用**粒子 + Shader 组合**；板块、河流地貌、等高线这类"几何形态现象"用**几何体 + 顶点位移**即可；裸眼3D 是叠加在所有现象之上的**相机/渲染层**技术，与具体现象解耦。

### 1.2 现有 earth.html 可复用基础

- `THREE.PerspectiveCamera` + `OrbitControls`：可直接挂载锋面/气旋场景
- `THREE.SphereGeometry(earthRadius, 64, 64)`：大气环流、洋流需复用地球本体作为载体
- `earth-optimization.js`：资源预加载/内存管理可复用
- 切换图层逻辑（satellite/topo/political）可扩展为"锋面/气旋/洋流"模式切换

## 二、锋面系统（冷锋 / 暖锋 / 准静止锋）

### 2.1 教学要点（学生易错点）

| 易错点 | 正确认知 | 3D 应重点呈现 |
|---|---|---|
| 混淆冷暖气团"谁主动" | 冷锋=冷气团主动楔入抬升暖气团；暖锋=暖气团主动爬升到冷气团上方 | 气团运动方向的动态箭头 + 抬升轨迹 |
| 锋面坡度差异 | 冷锋坡陡（1:50~1:100），暖锋坡缓（1:100~1:150） | 侧视图锋面斜面倾角对比 |
| 云系与降水带宽度 | 冷锋窄而急（积雨云、阵性降水）；暖锋宽而缓（层状云、连续性降水） | 云粒子分布范围 + 降水粒子密度 |
| 准静止锋"来回摆动" | 冷暖气团势均力敌，锋面南北摆动（梅雨、昆明准静止锋） | 锋面位置周期性往复动画 |
| 降水位置在锋面前后 | 冷锋降水在锋后/锋线附近；暖锋降水在锋前 | 降水粒子相对锋面的空间位置 |

### 2.2 3D 可视化方案

**推荐：双色粒子气团 + Shader 锋面斜面 + 降水粒子三层组合**

```
┌──────────── 侧视图（教学核心视角）─────────────┐
│  暖气团（红/橙粒子，缓慢翻涌）                  │
│        ╱────────── 锋面斜面（Shader 渐变）       │
│      ╱          ◇ 积雨云粒子簇（冷锋）            │
│    ╱            │ │ │ 降水粒子下落              │
│  ╱              ↓                                │
│ 冷气团（蓝/青粒子，快速推进 →）地面              │
└──────────────────────────────────────────────┘
```

- **气团表现**：两团不同颜色粒子（冷=青蓝、暖=橙红），各自用噪声场扰动模拟"翻涌"。**不建议用体积云 ray marching**——K12 教学需要清晰边界而非真实感，粒子团边界更易辨识。
- **锋面斜面**：用一个 `PlaneGeometry` 倾斜放置，自定义 Fragment Shader 渲染"渐变半透明带"，倾角按冷锋陡/暖锋缓设置。这是表现**坡度差异**的最直接方式。
- **降水粒子**：在锋面附近 spawn 短生命周期粒子，向下加速运动；冷锋降水带窄而密、暖锋宽而疏。
- **是否需要自定义 Shader**：**需要**。锋面斜面的渐变、云系分布的密度场、降水强度，用 ShaderMaterial 的 `fragmentShader` 控制 uDensity uniform 最优雅。纯 PointsMaterial 无法做"锋面附近密度渐变"。

### 2.3 Three.js 实现伪代码

```javascript
// === 锋面系统核心结构 ===
const frontGroup = new THREE.Group();

// 1. 冷气团粒子（青蓝，右侧，向左推进）
const coldParticles = createAirMass({
  color: 0x4a9eff, count: 8000, region: { x:[-3,3], y:[0,1.5], z:[-2,2] },
  velocity: new THREE.Vector3(-0.02, 0, 0), // 主动推进
  turbulence: 0.3
});

// 2. 暖气团粒子（橙红，左侧，被抬升）
const warmParticles = createAirMass({
  color: 0xff7a45, count: 8000, region: { x:[-6,-3], y:[0,2.5], z:[-2,2] },
  velocity: new THREE.Vector3(0, 0.01, 0), // 被迫抬升
  turbulence: 0.5
});

// 3. 锋面斜面（ShaderMaterial 控制坡度 + 渐变）
const frontSlope = new THREE.Mesh(
  new THREE.PlaneGeometry(8, 4, 1, 1),
  new THREE.ShaderMaterial({
    uniforms: {
      uColdColor: { value: new THREE.Color(0x4a9eff) },
      uWarmColor: { value: new THREE.Color(0xff7a45) },
      uDensity:   { value: 0.6 },
      uTime:      { value: 0 }
    },
    transparent: true,
    vertexShader: `
      varying vec2 vUv;
      void main(){ vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position,1.0); }
    `,
    fragmentShader: `
      varying vec2 vUv;
      uniform vec3 uColdColor, uWarmColor; uniform float uDensity, uTime;
      void main(){
        // 沿锋面方向渐变 + 噪声扰动模拟云带
        float n = sin(vUv.x*20.0 + uTime)*0.5+0.5;
        vec3 col = mix(uColdColor, uWarmColor, vUv.x);
        float a = uDensity * (0.4 + 0.6*n) * smoothstep(0.0,0.2,vUv.y)*smoothstep(1.0,0.8,vUv.y);
        gl_FragColor = vec4(col, a);
      }`
  })
);
frontSlope.rotation.x = -Math.PI/2;      // 横向铺开
frontSlope.rotation.z = THREE.MathUtils.degToRad(60); // 冷锋陡（60°）；暖锋改 30°

// 4. 降水粒子（锋面附近 spawn，下落）
const rainParticles = createPrecipitation({
  spawnArea: frontSlope.position, // 跟随锋面
  count: 3000, fallSpeed: -0.08, life: 60
});

frontGroup.add(coldParticles, warmParticles, frontSlope, rainParticles);

// === 切换锋面类型 ===
function switchFront(type){ // 'cold' | 'warm' | 'stationary'
  if(type==='cold'){ frontSlope.rotation.z = degToRad(60); coldParticles.setVel(-0.02,0,0); }
  if(type==='warm'){ frontSlope.rotation.z = degToRad(30); warmParticles.setVel(0.01,0,0); /* 暖气团主动 */ }
  if(type==='stationary'){
    // 锋面来回摆动
    const t = clock.getElapsedTime();
    frontSlope.position.x = Math.sin(t*0.5)*1.5;
  }
}
```

> `createAirMass` 封装：内部用 `THREE.Points` + `BufferGeometry`，每帧在 `onBeforeRender` 中更新粒子位置数组（CPU 方案，万级可接受；GPU 方案见 §4）。

## 三、气旋与反气旋

### 3.1 教学要点（学生易错点）

| 易错点 | 正确认知 |
|---|---|
| 南北半球旋转方向 | 北半球气旋=逆时针辐合，反气旋=顺时针辐散；南半球反之 |
| 气压与气流关系 | 气旋=低压中心（气流上升，多阴雨）；反气旋=高压中心（气流下沉,多晴朗） |
| 辐合 vs 辐散 | 气旋近地面辐合、高空辐散；反气旋近地面辐散、高空辐合 |
| 锋面气旋 | 温带气旋常与冷锋、暖锋结合（锋面气旋模型），冷锋追上暖锋→锢囚 |
| "气旋=台风"误解 | 台风是热带气旋；温带气旋是锋面气旋，结构不同 |

### 3.2 3D 可视化方案

**推荐：极坐标流场粒子 + 中心气压柱 + 锋面叠加**

- **粒子流场**（首选）：在以低压中心为原点的极坐标网格上分布粒子，速度场 `v = ω × r`（角速度叉乘半径），方向按半球/气旋类型切换。粒子拖尾形成可见螺旋。
- **矢量场箭头**（备选/辅助）：在网格点上画箭头，适合静态判读，但动态感弱于粒子。
- **中心气压柱**：用一个半透明圆柱表示上升（气旋）或下沉（反气旋）气流，配箭头方向。
- **锋面气旋叠加**：在气旋上叠加 §2 的冷锋/暖锋斜面，冷锋在西侧追击，暖锋在东侧先行——这是高中地理重点模型。

> **选粒子流场而非矢量场**：粒子拖尾能体现"辐合/辐散"的动态汇聚过程，箭头只能表达瞬时方向。教学目标是让学生"看出旋转和汇聚趋势"。

### 3.3 Three.js 实现伪代码

```javascript
// === 气旋流场粒子 ===
const PARTICLE_COUNT = 12000;
const positions = new Float32Array(PARTICLE_COUNT * 3);
const lives = new Float32Array(PARTICLE_COUNT);

function initParticle(i){
  const r = Math.random()*5 + 0.5;        // 距中心半径
  const theta = Math.random()*Math.PI*2;
  positions[i*3]   = r*Math.cos(theta);
  positions[i*3+1] = 0;
  positions[i*3+2] = r*Math.sin(theta);
  lives[i] = Math.random()*100;
}
for(let i=0;i<PARTICLE_COUNT;i++) initParticle(i);

const geom = new THREE.BufferGeometry();
geom.setAttribute('position', new THREE.BufferAttribute(positions,3));
const cyclonePoints = new THREE.Points(geom, new THREE.PointsMaterial({
  size:0.05, color:0x66ccff, transparent:true, opacity:0.8, blending:THREE.AdditiveBlending
}));

// 每帧更新：极坐标流场
function updateCyclone(dt, type){ // 'cyclone_N'|'anticyclone_N'|'cyclone_S'
  const dir = (type==='cyclone_N'||type==='anticyclone_S') ? -1 : 1; // 逆时针
  const inout = type.startsWith('cyclone') ? -1 : 1; // 气旋辐合(向心),反气旋辐散(离心)
  for(let i=0;i<PARTICLE_COUNT;i++){
    let x=positions[i*3], z=positions[i*3+2];
    let r = Math.hypot(x,z), theta = Math.atan2(z,x);
    const omega = 0.5 / (r+0.5);          // 角速度（内圈快）
    theta += dir*omega*dt;
    r += inout*0.01*dt;                    // 辐合/辐散
    if(r<0.3||r>5.5) { initParticle(i); continue; }
    positions[i*3]   = r*Math.cos(theta);
    positions[i*3+2] = r*Math.sin(theta);
    positions[i*3+1] += (type.startsWith('cyclone')?0.005:-0.005)*dt; // 气旋上升/反气旋下沉
    if((lives[i]-=dt)<=0) initParticle(i);
  }
  geom.attributes.position.needsUpdate = true;
}

// === 锋面气旋叠加（高中重点）===
const cycloneSystem = new THREE.Group();
cycloneSystem.add(cyclonePoints);
cycloneSystem.add(frontCold.clone()); // 西侧冷锋
cycloneSystem.add(frontWarm.clone()); // 东侧暖锋
cycloneSystem.add(riseColumn);        // 中心上升气流柱
```

## 四、大气环流（三圈环流 / 气压带风带 / 季风）

### 4.1 教学要点（学生易错点）

| 易错点 | 正确认知 |
|---|---|
| 三圈环流每个环的方向 | 哈德莱环（0–30°）上升在赤道下沉在副热带；费雷尔环（30–60°）与哈德莱反向；极地环（60–90°）上升在副极地下沉在极地 |
| 信风 vs 西风带 | 信风（0–30°）由副热带高压吹向赤道，偏转为东北信风/东南信风；西风带（30–60°）由副热带吹向副极地 |
| 气压带数量 | 7 个气压带（赤道低压、副热带高压×2、副极地低压×2、极地高压×2）+ 6 个风带 |
| 1月/7月气压中心移动 | 太阳直射点移动 → 气压带风带随之南北移动；1月南移、7月北移 |
| 季风成因 | 海陆热力差异（东亚）+ 气压带风带移动（南亚，夏季东南信风越过赤道偏转成西南季风） |

### 4.2 3D 可视化方案

**推荐：地球本体 + 经圈剖面环流 + 地表风带粒子流**

这是三个子模块的组合：

1. **三圈环流剖面**（教学重点）：在地球侧切一个经圈大圆面上，画三个闭合环流箭头。用 `THREE.Line` + `TubeGeometry` 画带箭头的环，方向按哈德莱/费雷尔/极地设置。可"剖切显示"——只显示朝向相机的一侧经圈。
2. **气压带风带**：地球表面按纬度分带着色（低压=蓝、高压=红），叠加沿纬线方向流动的粒子流（东北信风、西风、极地东风）。粒子速度场 `v = windDir(纬度)`。
3. **季风环流**：1月/7月两套风向粒子，切换时展示东亚（西北↔东南）和南亚（东北↔西南）季风反转。
4. **气压带移动动画**：uniform `uSeasonOffset` 控制 7 个气压带的纬度偏移，0→夏、1→冬来回插值。

> **GPU 粒子方案**（洋流/全球风场必用）：当粒子 >5 万时，CPU 更新 position 数组会卡。用 `ShaderMaterial` + `texture` 存储粒子位置（ping-pong RT），顶点着色器读取纹理计算下一帧位置。这是 earth.nullschool.net 的核心技巧。三圈环流粒子量不大（<1万）可 CPU。

### 4.3 Three.js 实现伪代码

```javascript
// === 子模块1：三圈环流剖面（经圈大圆）===
function buildCellRing(){
  const ring = new THREE.Group();
  const cells = [
    {name:'Hadley', latRange:[0,30],  dir:[1,-1]},   // 赤道上升,副热带下沉
    {name:'Ferrel', latRange:[30,60], dir:[-1,1]},   // 副热带上升,副极地下沉(反向)
    {name:'Polar',  latRange:[60,90], dir:[1,-1]}    // 副极地上升,极地下沉
  ];
  cells.forEach(c=>{
    const curve = buildCellCurve(c.latRange, c.dir); // 返回 CatmullRomCurve3
    const tube = new THREE.Mesh(new THREE.TubeGeometry(curve,80,0.04,8,true),
      new THREE.MeshBasicMaterial({color:0xffcc00}));
    ring.add(tube);
  });
  return ring;
}

// === 子模块2：地表风带粒子（GPU 方案要点）===
const N = 50000;
const windGeom = new THREE.BufferGeometry();
const aLatLon = new Float32Array(N*2); // 每粒子的(纬度,经度)作为属性

    attribute vec2 aLatLon; uniform float uTime,uSeason;
    varying float vAlpha;
    vec3 latLonToVec3(float lat,float lon,float r){
      float phi=radians(lat+90.0), theta=radians(lon);
      return vec3(r*sin(phi)*cos(theta),r*cos(phi),r*sin(phi)*sin(theta));

    void main(){
      float lat=aLatLon.x, lon=aLatLon.y;
      // 风向随纬度分带 + 季节偏移

      else dir=vec2(-1.0,0.2);                 // 极地东风
      lon += dir.x*uTime*5.0;
      lat += dir.y*uTime*2.0;
      vec3 pos = latLonToVec3(lat,lon,1.01) * 100.0; // earthRadius=100
      vAlpha = 0.6;
      gl_Position = projectionMatrix*modelViewMatrix*vec4(pos,1.0);
      gl_PointSize = 2.0;
    }`,
  fragmentShader:`varying float vAlpha; void main(){ gl_FragColor=vec4(1.0,0.9,0.6,vAlpha); }`,
  transparent:true, blending:THREE.AdditiveBlending
});
const surfaceWind = new THREE.Points(windGeom, windMat);
```

## 五、洋流（分布 / 厄尔尼诺）

### 5.1 教学要点（学生易错点）

| 易错点 | 正确认知 |
|---|---|
| 暖流/寒流判定 | 由低纬流向高纬=暖流；由高纬流向低纬=寒流（看流向而非水温绝对值） |
| 北半球副热带环流方向 | 北顺南逆（顺时针）；南半球反之 |
| 北太平洋洋流组成 | 北赤道暖流→黑潮→北太平洋暖流→加利福尼亚寒流（闭合环） |
| 厄尔尼诺机理 | 信风减弱→赤道暖水东移→秘鲁寒流减弱→太平洋东西温差减小 |
| 拉尼娜 | 厄尔尼诺的反相，信风增强，赤道东太平洋更冷 |
| 西风漂流 | 南半球 40–60°S 西风漂流为寒流（受南极影响） |

### 5.2 3D 可视化方案

**推荐：地球表面流线粒子 + 暖/寒色编码 + 厄尔尼诺切换**

- **流线粒子**（首选）：在地球表面（r=earthRadius×1.005）沿洋流路径分布粒子，沿预定义洋流曲线运动。暖流粒子=红橙、寒流=蓝青。流线粒子比箭头矢量场更"连续"，能看出闭合环流。
- **洋流路径曲线**：预定义主要洋流为 `CatmullRomCurve3`（控制点按真实地理坐标），粒子沿曲线运动 + 拖尾。
- **厄尔尼诺切换**：两套粒子状态（正常/厄尔尼诺），切换时赤道东太平洋粒子颜色由蓝→红、流速变化，并标注 SST 等温线偏移。
- **表层 vs 深层**：表层粒子在球面，深层（温盐环流）粒子在球内 r=0.95 处用反向流动表现。

> **选流线粒子而非箭头矢量场**：洋流是连续流动，箭头离散且占显存。流线粒子拖尾能直观看出"环流闭合"。

### 5.3 Three.js 实现伪代码

```javascript
// === 洋流路径（经纬度控制点→球面曲线）===
function latLonToVec3(lat,lon,r=100){
  const phi=radians(lat+90), theta=radians(lon);
  return new THREE.Vector3(r*Math.sin(phi)*Math.cos(theta), r*Math.cos(phi), r*Math.sin(phi)*Math.sin(theta));
}
const currents = {
  kuroshio: { pts:[[25,130],[35,140],[45,150],[50,160]], type:'warm' },  // 黑潮暖流
  california: { pts:[[50,160],[40,130],[25,120]], type:'cold' },          // 加利福尼亚寒流
  humboldt:  { pts:[[5,-90],[-15,-85],[-30,-80],[-45,-75]], type:'cold' } // 秘鲁寒流
};

function buildCurrentFlow(name, def){
  const curve = new THREE.CatmullRomCurve3(def.pts.map(p=>latLonToVec3(...p,101)));
  const color = def.type==='warm' ? 0xff6b35 : 0x4ab3ff;
  // 粒子沿曲线运动
  const N=800; const pos=new Float32Array(N*3); const t=new Float32Array(N);
  for(let i=0;i<N;i++){ t[i]=Math.random(); curve.getPointAt(t[i], pos.subarray(i*3)); }
  const g=new THREE.BufferGeometry();
  g.setAttribute('position',new THREE.BufferAttribute(pos,3));
  g.setAttribute('aT',new THREE.BufferAttribute(t,1));
  const m=new THREE.ShaderMaterial({
    uniforms:{uCurvePts:{value:def.pts.map(p=>latLonToVec3(...p,101))},uColor:{value:new THREE.Color(color)},uTime:{value:0}},
    vertexShader:`attribute float aT; uniform float uTime; /* 用 aT+uTime 查表曲线点 */`,
    fragmentShader:`uniform vec3 uColor; void main(){gl_FragColor=vec4(uColor,0.8);}`,
    transparent:true,blending:THREE.AdditiveBlending
  });
  return new THREE.Points(g,m);
}

// === 厄尔尼诺切换 ===
function setElNino(on){
  // 秘鲁寒流粒子颜色 蓝色→偏红，赤道东太平洋 SST 升高
  humboldtFlow.material.uniforms.uColor.value.set(on?0xff8855:0x4ab3ff);
  // 信风减弱→赤道暖水东移：调整赤道洋流粒子速度
}
```

- **板块边界**：在地球表面用 `THREE.Line`/`TubeGeometry` 绘制六大板块边界，按类型着色（张裂=绿色、挤压=红色、转换=黄色）。

## 七、河流地貌（V 谷 / 冲积扇 / 河曲 / 三角洲）

### 7.1 教学要点（学生易错点）

| 易错点 | 正确认知 |
|---|---|
| 上中下游主导外力 | 上游=下蚀（V谷）；中游=侧蚀（河曲）；下游=沉积（三角洲） |
| V 谷成因 | 河流下切侵蚀，谷坡陡峭，横剖面呈 V 形 |
| 冲积扇位置 | 山区河流出山口（山麓），流速骤减，沉积呈扇形 |
| 牛轭湖形成 | 河曲颈被裁弯取直后，废弃弯曲河道成湖 |
| 三角洲形成条件 | 河流挟沙量大 + 入海口流速骤减 + 海水顶托 + 无强潮流 |
| 河流阶地 | 地壳抬升→下切加深，原河漫滩成阶地，多级阶地=多次抬升 |

### 7.2 3D 可视化方案

**推荐：分河段 3D 地形 + 水流粒子 + 演变时间轴**

- **分河段场景**：上游/中游/下游/出山口四个独立 3D 微场景，每场景一个 `PlaneGeometry` 用 heightmap 生成地形 + 水流粒子。
  - 上游：高差大的 V 谷地形（heightmap 深切）
  - 出山口：扇形沉积地形
  - 中游：宽谷 + 蜿蜒河道
  - 下游：平缓 + 扇状三角洲
- **水流粒子**：沿河道曲线运动的蓝色粒子，表现水流方向与速度。
- **演变动画**：V 谷加深、河曲发育、牛轭湖裁弯取直、三角洲向海推进的时间轴动画（用 morph 或 heightmap 插值）。
- **等高线联动**：与 §8 联动，每河段可切换显示等高线，理解"V 形等高线指向上游"。

> **地形用 heightmap 顶点位移**：`PlaneGeometry` 顶点 y 坐标按 heightmap 纹理采样位移。这是 §8 等高线方案的地形基础，复用同一套。

```javascript
// === V 谷地形（heightmap 顶点位移）===
function buildValleyTerrain(heightFn){ // heightFn(x,z)=>y
  const geo = new THREE.PlaneGeometry(20,20,128,128);

}

}
```

## 八、等高线地形图（2D↔3D 联动）

### 8.1 教学要点（学生易错点）

| 易错点 | 正确认知 |
|---|---|
| 等高线疏密与坡度 | 密=陡坡，疏=缓坡 |
| 等高线凸向判地形 | 等高线向高处凸出=山谷；向低处凸出=山脊 |
| 鞍部判读 | 两山顶之间低地，等高线呈"马鞍形" |
| 陡崖表示 | 等高线重合处，用陡崖符号 |
| 分层设色 | 绿(低)→黄→棕→白(高/雪) |
| 2D↔3D 对应 | 这是教学关键点：等高线是3D地形的"水平切片投影" |

### 8.2 3D 可视化方案

**推荐：3D 地形 + 等高线投影联动 + 水平切片动画**

这是教学价值最高的现象，核心是"2D 等高线 ↔ 3D 地形"的双向对应：

- **3D 地形**：heightmap 顶点位移 + 分层设色 ShaderMaterial（按顶点高度着色）。
- **等高线投影**：在 3D 地形下方（地面平面）用 Canvas2D 绘制等高线，或在地形 Shader 中根据高度阈值绘制等高线（`fract(height/interval)` 接近 0 时描黑）。
- **水平切片动画**（教学神器）：一个水平平面从下往上扫过 3D 地形，扫到的等高线高亮，对应 2D 投影上的等高线同步高亮——这能让学生"看出"等高线是怎么来的。
- **交互**：鼠标悬停 3D 地形某点 → 显示该点海拔 + 对应等高线；点击山顶/山脊/山谷/鞍部/陡崖 → 高亮该地形特征并标注。

> **核心 Shader**：等高线绘制用 `fragmentShader` 中 `float line = abs(fract(vHeight/uInterval)-0.5); if(line<0.02) col=mix(col,black,0.7);`。这是最优雅的等高线渲染方式，无需额外几何。

```javascript
const pos = terrainGeo.attributes.position;
for(let i=0;i<pos.count;i++){
  const u = i % 257, v = Math.floor(i/257);
  const h = sampleHeight(img, u/256, v/256) * 8; // 放大高程
  pos.setZ(i, h);
}
terrainGeo.computeVertexNormals();

const terrainMat = new THREE.ShaderMaterial({
  uniforms:{
    uInterval:{value:1.0},  // 等高线间距
    uMinH:{value:0}, uMaxH:{value:8}
  },
  vertexShader:`
    varying float vH; varying vec3 vNormal;
    void main(){
      vH = position.z; vNormal = normal;
      gl_Position = projectionMatrix*modelViewMatrix*vec4(position,1.0);
    }`,
  fragmentShader:`
    varying float vH; varying vec3 vNormal; uniform float uInterval,uMinH,uMaxH;
    void main(){
      // 分层设色
      float t = (vH-uMinH)/(uMaxH-uMinH);
      vec3 low=vec3(0.2,0.6,0.2), mid=vec3(0.9,0.8,0.3), high=vec3(0.5,0.35,0.2), snow=vec3(1.0);
      vec3 col = t<0.4 ? mix(low,mid,t/0.4)
                : t<0.8 ? mix(mid,high,(t-0.4)/0.4)
                : mix(high,snow,(t-0.8)/0.2);
      // 等高线
      float line = abs(fract(vH/uInterval)-0.5);
      if(line<0.02) col = mix(col, vec3(0.0), 0.7);
      // 简单光照
      float light = max(0.0, dot(vNormal, normalize(vec3(0.5,0.5,1.0))));
      col *= 0.6+0.4*light;
      gl_FragColor = vec4(col,1.0);
    }`
});
const terrain = new THREE.Mesh(terrainGeo, terrainMat);

// === 水平切片扫描动画 ===
const slicePlane = new THREE.Mesh(
  new THREE.PlaneGeometry(40,40),
  new THREE.MeshBasicMaterial({color:0xffff00,transparent:true,opacity:0.3,side:THREE.DoubleSide})
);
function scanContour(t){ // t:0→1 扫描高度

  terrainMat.uniforms.uHighlightH.value = slicePlane.position.z; // shader 高亮该高度等高线
}
```

## 九、裸眼3D 切换技术方案

### 9.1 三种技术路径对比

| 方案 | 原理 | 实现复杂度 | 立体效果 | 是否需摄像头 | 适合现象 |
|---|---|---|---|---|---|
| **A. Head-Coupled Perspective（HCP）** | MediaPipe Face Mesh 追踪头部位置 → 实时调整 Three.js 相机位置/视角 | 中 | **强**（有纵深错觉，单屏即可） | 是 | 锋面、地形、河流地貌 |
| **B. StereoCamera 双视图** | Three.js `StereoEffect` 渲染左右眼双画面，需裸眼3D 显示器或柱透镜屏 | 低（API 现成） | 强（真双目）但**普通屏无用** | 否 | 仅在裸眼3D 硬件屏上 |
| **C. CSS 3D 视差** | 多层 DOM 用 `translate3d` 按鼠标/陀螺仪位移产生视差 | 低 | 弱（伪3D，无真纵深） | 否 | 2D 标注层、UI 装饰 |

### 9.2 推荐方案：A（Head-Coupled Perspective）

**理由**：K12 教学场景是普通教室的普通屏幕/投影，方案 B 需要 per pee-through 硬件屏不现实；方案 C 无真纵深。方案 A 只需一个摄像头（笔记本自带），通过追踪学生头部位置，实时调整 Three.js 相机，让画面"跟着头动"，大脑产生强烈的"窗口看进3D"错觉——这是 Johnny Lee 2007 年 Wii Remote 白板技术的现代 webcam 版本。

### 9.3 实现伪代码（MediaPipe + Three.js）

```javascript
// === MediaPipe Face Mesh 头部追踪 ===
import { FaceMesh } from '@mediapipe/face_mesh';
const faceMesh = new FaceMesh({ locateFile: f=>`https://cdn.jsdelivr.net/npm/@mediapipe/face_mesh/${f}` });
faceMesh.setOptions({ maxNumFaces:1, refineLandmarks:true, minDetectionConfidence:0.5 });

let headX=0, headY=0, headZ=0;
faceMesh.onResults(res=>{
  if(!res.multiFaceLandmarks?.length) return;
  const lm = res.multiFaceLandmarks[0];
  // 用鼻尖(1号点)归一化坐标估算头部位置
  headX = (lm[1].x - 0.5) * 2;    // -1~1 左右
  headY = (0.5 - lm[1].y) * 2;    // -1~1 上下
  const faceW = Math.abs(lm[234].x - lm[454].x); // 脸宽→估算前后距离
  headZ = (0.15 - faceW) * 5;     // 越近脸越大
});

// === Three.js 相机随头部位置偏移（HCP 核心）===
function updateCameraHCP(){
  const offsetScale = 3; // 视差强度
  camera.position.x = baseCamX + headX * offsetScale;
  camera.position.y = baseCamY + headY * offsetScale;
  camera.position.z = baseCamZ - headZ * offsetScale;
  camera.lookAt(sceneTarget);       // 始终看向场景中心
  renderer.render(scene, camera);
  requestAnimationFrame(updateCameraHCP);
}

// 摄像头视频流
const video = document.createElement('video');
navigator.mediaDevices.getUserMedia({video:{width:320,height:240}}).then(stream=>{
  video.srcObject = stream;
  video.onloadedmetadata = ()=> video.play();
});
// 每帧送入 MediaPipe
async function detectLoop(){
  await faceMesh.send({image:video});
  requestAnimationFrame(detectLoop);
}
detectLoop(); updateCameraHCP();
```

### 9.4 方案 B（StereoEffect）何时用

仅在教室配备**柱透镜裸眼3D 显示器**或**视差屏障屏**时启用。Three.js 内置：

```javascript
import { StereoEffect } from 'three/examples/jsm/effects/StereoEffect.js';
const effect = new StereoEffect(renderer);
effect.setSize(width, height);
// render 时用 effect.render(scene, camera) 替代 renderer.render
```

> 普通屏幕上 StereoEffect 会显示左右分屏双画面，学生需交叉眼或戴红蓝眼镜，不适合课堂。**默认不启用**。

### 9.5 哪些现象适合裸眼3D（结论矩阵）

| 现象 | 裸眼3D 价值 | 推荐方案 | 说明 |
|---|---|---|---|
| 锋面系统 | ★★★★★ | HCP | 立体斜面 + 抬升纵深，最受益 |
| 等高线地形 | ★★★★★ | HCP | 山高谷深，等高线疏密立体化 |
| 河流地貌 | ★★★★ | HCP | V谷深切、三角洲推进 |
| 俯冲带剖切 | ★★★ | HCP | 板块向下插入纵深 |
| 气旋/反气旋 | ★★ | 可选 | 俯视现象，收益有限 |
| 大气环流 | ★ | 不推荐 | 全球分布，俯视即可 |
| 洋流 | ★ | 不推荐 | 球面现象，立体感来自地球弧度 |

### 9.6 性能与降级

- MediaPipe Face Mesh 在中端笔记本约 15–30 fps 检测，配合 Three.js 60fps 渲染需异步解耦（检测在 Worker/低频，相机平滑插值在 RAF）。
- 降级策略：无摄像头/检测失败 → 回退到鼠标位置驱动相机（mouseX/Y 替代 headX/Y），仍有视差效果。
- 性能预算：开启 HCP 时建议关闭阴影、降低粒子数 30%。

| 优先级 | 现象 | 难度 | 工作量 | 裸眼3D | 理由 |
|---|---|---|---|---|---|
