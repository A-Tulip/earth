## 一、结论速览（TL;DR）

| 能力域 | 火山引擎是否值得接入 | 核心理由 |
|---|---|---|
| **AR / VR / 3D 渲染** | ❌ **不推荐** | 火山引擎 Web AR SDK（`@volcengine/webar`）是**人脸美化/滤镜/贴纸 SDK**，面向直播与短视频，**与地理 3D 可视化无关**；无自研 3D 地理渲染引擎，无 WebXR 地理能力 |
| **AI 语音识别（ASR）** | ✅ **强烈推荐** | 豆包语音识别大模型 2.0 支持双向流式、中英混合、抗噪，**远超浏览器 Web Speech API**（后者仅 Chrome 且识别质量不稳定） |
| **AI 语音合成（TTS）** | ✅ **推荐** | 豆包语音合成大模型支持情感韵律、流式输出、SSML，适合 AI 地理助教"开口说话" |
| **豆包大模型（LLM）** | ✅ **强烈推荐** | doubao-1.5-pro / lite 价格极低（输入 0.8 元/百万 token），支持流式，适合做 AI 地理助教对话 |
| **实时语音对话（端到端）** | ⚠️ **可选/进阶** | 豆包 Seeduplex 全双工语音大模型延迟 ~80ms、可打断，但接入复杂度高，建议作为 V2 目标 |
| **地图 / 卫星影像 / DEM** | ❌ **不适用** | 火山引擎**没有公开的地图 API / 卫星影像 / DEM 高程服务**，此项应继续用 Cesium（见 `地图API调研报告.md`） |
| **裸眼 3D** | ❌ 火山引擎无相关 Web SDK | 火山引擎虽位列裸眼 3D 一体机厂商，但那是**硬件显示方案**，不提供 Web 端裸眼 3D SDK。裸眼 3D 需自研（见第九节） |

> **一句话总结**：火山引擎对本项目的价值集中在 **AI 语音三件套（ASR + TTS + 豆包 LLM）**，用它替换现有的 Web Speech API 可实现"AI 语音与地球功能深度交互"；3D/地图/裸眼 3D 均不应依赖火山引擎。

## 三、AR / VR / 3D 能力详评

### 3.1 Web AR SDK（`@volcengine/webar`）

- **官方文档**：https://www.volcengine.com/docs/83843/1166805
- **安装方式**：`npm install @volcengine/webar` 或 CDN 引入
- **实际用途**：**AR 人脸特效**——人脸识别 + 美颜/美妆/贴纸/滤镜，面向直播、短视频、营销互动场景
- **技术栈**：基于 WebGL + 人脸关键点检测，**不是通用 3D 渲染引擎**
- **与地理 3D 的关系**：**无关**。该 SDK 处理的是摄像头画面上叠加 AR 贴纸，无法用于 3D 地球渲染、地形可视化等场景

```js
// 火山引擎 Web AR SDK 的真实用法——人脸 AR 特效，与地理无关
import { ARSession, ARSDK } from "@volcengine/webar";
const session = ARSDK.createSession({ canvas, authorization: ... });
await session.start();
// 之后添加的是：美颜、贴纸、滤镜——不是 3D 地球
```

### 3.2 智能美化特效 SDK（CV）

- **官方文档**：https://www.volcengine.com/docs/6705/102013/
- **能力**：美颜、美形、美体、美妆、滤镜、贴纸
- **支持平台**：Android、iOS、Windows、Mac、Linux（**无纯 Web/JS SDK**，鸿蒙有 har 包）
- **与本项目关系**：**完全无关**。这是抖音/剪映同款美颜能力，不是地理 3D

### 3.3 裸眼 3D

- 火山引擎虽被列入"2025 年中国裸眼 3D 一体机厂商"名单（与华为、百度、科大讯飞等并列），但这是**硬件显示设备**层面的参与，**不提供 Web 端裸眼 3D 渲染 SDK**
- 火山引擎多媒体实验室在 NeurIPS 2025 发表了视频时空采样论文（TempSamp），属于视频大模型研究，**非面向开发者的裸眼 3D SDK**
- **结论**：火山引擎对 Web 端裸眼 3D **无可集成能力**

### 3.4 3D 渲染引擎

- 火山引擎**没有自研的通用 3D 渲染引擎**（不像 Cesium / Three.js / Mapbox）
- 视频相关 3D 能力（如视频创作 SDK 中的 3D 特效）均围绕视频后期，不适用于实时地理可视化
- **结论**：3D 地理渲染应继续使用 **Three.js（现有）+ Cesium（见地图调研报告推荐）**

### 3.5 AR/VR/3D 小结

| 需求 | 火山引擎能否满足 | 推荐方案 |
|---|---|---|
| 3D 地球渲染 | ❌ 不能 | Three.js（现有） |
| 真实地形 / DEM | ❌ 不能 | Cesium（见 `地图API调研报告.md`） |
| 裸眼 3D 切换 | ❌ 无 SDK | 自研（第九节方案） |
| AR 人脸贴纸 | ✅ 能（但本项目不需要） | — |

## 四、AI 语音能力详评（ASR / TTS / 豆包大模型）

> **这是火山引擎对本项目最有价值的部分。** 当前 `earth.html` 使用浏览器原生 `Web Speech API`（`SpeechRecognition`），存在三大痛点：① 仅 Chrome 有效；② 中文识别准确率不稳定；③ 无法做自然语音合成（`speechSynthesis` 音色机械）。火山引擎可全面解决。

### 4.1 豆包语音识别大模型（ASR 2.0）

- **产品页**：https://www.volcengine.com/product/asr
- **文档**：https://www.volcengine.com/docs/6561/1354871
- **最新版本**：Doubao-Seed-ASR-2.0（2025-12 发布）
- **核心能力**：

| 能力 | 说明 |
|---|---|
| **双向流式识别** | 边说边出文字，WebSocket 双向传输，近实时 |
| **大模型驱动** | 上下文理解能力强，关键词召回率提升 20% |
| **中英文混合** | 原生支持中英混说 |
| **抗噪能力** | 弱化背景音/噪声影响——适合教室环境 |
| **专有名词识别** | 地理专有名词（如"喜马拉雅""安第斯山脉"）识别更准 |
| **一句话识别** | ≤60s 短语音，适合语音指令 |
| **录音文件识别** | ≤5h 音频转写，适合课堂录音分析 |

- **产品类型**：大模型流式 ASR / 大模型录音文件识别 / 一句话识别 / 流式 ASR / 录音文件识别极速版
- **免费额度**：每个豆包语音应用赠送 **20 小时**流式识别 + **20 小时**大模型流式识别

### 4.2 豆包语音合成大模型（TTS 2.0）

- **产品页**：https://www.volcengine.com/product/tts
- **文档**：https://www.volcengine.com/docs/6561/1257543
- **核心能力**：

| 能力 | 说明 |
|---|---|
| **大模型合成** | 根据上下文智能预测情绪、语调，超自然 |
| **流式输出** | 非流式输入 + 流式输出，边生成边播放，降低首字延迟 |
| **SSML 支持** | 可标记停顿、语速、音量、发音等 |
| **情感表达** | 情绪演绎、韵律自然，远超传统 TTS |
| **声音复刻** | 5 秒录音即可定制专属音色（可做"地理老师"音色） |
| **多音色** | 丰富预置音色库 |

### 4.3 豆包实时语音大模型（Seeduplex）——进阶方案

- **产品页**：https://www.volcengine.com/product/realtime-voice-model
- **核心指标**：

| 指标 | 数值 |
|---|---|
| 端到端延迟 | **~80ms** |
| 语音识别准确率 | 97.3% |
| 全双工 | ✅ 支持同时说听 |
| **可打断** | ✅ 用户随时打断 AI 回复 |
| 情绪理解 | ✅ 理解用户语气情绪 |
| 联网能力 | ✅ 实时联网检索 |

- **接入方式**：通过火山引擎 RTC 对话式 AI，或火山方舟 API
- **适用场景**：AI 地理助教的"自然语音对话"——学生直接语音提问，AI 实时语音回答，可打断
- **注意**：接入复杂度较高（需 RTC + ASR + LLM + TTS 编排），建议作为 V2 目标

| **离线** | ✅ 可离线（部分） | ❌ 需联网 |

## 五、视觉 / 影像 / 地图能力详评

### 5.1 地图服务

- **结论**：火山引擎**没有公开的地图 JavaScript API**。中国地图服务市场由百度地图、高德地图（阿里）、腾讯地图主导，火山引擎不在此领域竞争。
- 本项目的地图需求已在 `地图API调研报告.md` 中确定方案（Cesium 为主引擎 + 高德补充中国 LBS），**不涉及火山引擎**。

### 5.2 卫星影像

- 火山引擎**无公开卫星影像服务**。
- 卫星影像应使用 Cesium ion（Bing 影像）或 Mapbox Satellite，见已有调研报告。

### 5.3 DEM 高程数据

- 火山引擎**无公开 DEM 高程数据服务**。
- DEM 应使用 Cesium World Terrain（quantized-mesh）或 Mapbox Terrain，见已有调研报告。

### 5.4 CV 视觉能力

- 火山引擎 CV 能力（智能美化特效）聚焦人脸/人体，**不含遥感影像分析、地理影像处理**。
- 与本项目地理可视化无关。

## 八、推荐集成方案

### 8.1 总体架构

```
┌─────────────────────────────────────────────────────┐
│                   前端（浏览器）                      │
│  ┌──────────┐  ┌──────────┐  ┌───────────────────┐  │
│  │ Three.js │  │ Cesium   │  │  AI 助教面板       │  │
│  │ 概念地球  │  │ 真实地貌  │  │  （对话 + 语音）   │  │
│  └──────────┘  └──────────┘  └───────┬───────────┘  │
│           ↑ 地球操作指令          ↑ 音频流/文本       │
│           │ Function Calling       │ WebSocket       │
└───────────┼───────────────────────┼─────────────────┘
            │                        │
┌───────────┼───────────────────────┼─────────────────┐
│           ▼   后端中转层（Node.js）  ▼                 │
│  ┌────────────────┐  ┌──────────────────────────┐   │
│  │ 豆包 LLM API   │  │ ASR / TTS WebSocket      │   │
│  │ (地理助教大脑)  │  │ (语音识别 / 语音合成)     │   │
│  └────────────────┘  └──────────────────────────┘   │
│           火山引擎（Volcengine）                      │
└──────────────────────────────────────────────────────┘
```

### 8.2 为什么需要后端中转

- **API Key 安全**：火山引擎所有 API 均需 AppID + Access Token 鉴权，**绝不能暴露在前端代码中**
- **流式代理**：ASR/TTS 的 WebSocket 流需要后端做协议转换（浏览器 ↔ 火山引擎 WebSocket）
- **LLM Function Calling 路由**：后端解析 LLM 返回的 function call，转发指令给前端控制地球

### 8.3 分阶段落地路径

| 阶段 | 任务 | 火山引擎服务 | 优先级 |
|---|---|---|---|
| **V1** | 后端中转层搭建（Node.js Express + WebSocket） | — | P0 |
| **V1** | 用豆包 ASR 替换 Web Speech API（语音指令识别） | ASR 流式 | P0 |
| **V1** | 用豆包 LLM 做 AI 地理助教对话（文本） | doubao-1.5-lite | P0 |
| **V1** | LLM Function Calling → 地球操作（"飞到北京"等） | doubao-1.5-pro | P1 |
| **V2** | 用豆包 TTS 让助教"开口说话"（语音播报回答） | TTS 大模型 | P1 |
| **V2** | 声音复刻定制"地理老师"音色 | 声音复刻 | P2 |
| **V3** | 接入 Seeduplex 实现全双工可打断语音对话 | 实时语音大模型 | P3 |

### 8.4 哪些功能用火山引擎、哪些用其他方案

| 功能 | 推荐方案 | 理由 |
|---|---|---|
| 语音识别 | ✅ **火山引擎 ASR** | 准确率/兼容性远超 Web Speech API |
| AI 对话 | ✅ **豆包 LLM** | 价格极低，中文能力强 |
| 语音合成 | ✅ **火山引擎 TTS** | 自然度远超浏览器 speechSynthesis |
| 3D 地球（概念） | Three.js（现有） | 火山引擎无 3D 地理引擎 |
| 3D 地球（真实地貌） | Cesium（见地图调研报告） | 火山引擎无 DEM/卫星影像 |
| 裸眼 3D 切换 | 自研 Three.js 方案（第九节） | 火山引擎无 Web 裸眼 3D SDK |
| 中国 POI/行政区 | 高德 JS API（见地图调研报告） | 火山引擎无地图服务 |

## 九、裸眼 3D 技术方案（不依赖火山引擎）

> 用户要求"裸眼 3D 切换"。真正的裸眼 3D（autostereoscopic）需要特殊硬件（柱状透镜/视差屏障屏幕）。在普通显示器上，"裸眼 3D"有以下 Web 实现路径：

### 9.1 方案对比

| 方案 | 原理 | 是否真裸眼3D | 实现难度 | 视觉效果 | 推荐 |
|---|---|---|---|---|---|
| **A. 头部追踪视差** | 用摄像头追踪头部位置，动态调整 3D 相机角度，产生"窗口效应" | ✅ 接近 | 中 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **B. Three.js StereoEffect（双视图）** | 渲染左右眼视图并排，用户交叉对眼观看 | ⚠️ 需交叉眼 | 低 | ⭐⭐⭐ | ⭐⭐ |
| **C. Three.js AnaglyphEffect（红蓝）** | 渲染红青分色左右眼视图，需红蓝眼镜 | ❌ 需眼镜 | 低 | ⭐⭐ | ⭐ |
| **D. Three.js ParallaxBarrierEffect** | 模拟视差屏障，并排像素交错 | ⚠️ 需特定屏幕 | 中 | ⭐⭐ | ⭐⭐ |
| **E. CSS 3D Transforms 视差** | 多层 DOM 元素 + `perspective` + 鼠标偏移 | ❌ 伪 3D 视差 | 低 | ⭐⭐ | ⭐⭐⭐ |
| **F. WebXR Device API** | 标准 VR/AR API | ❌ 需头显 | 高 | ⭐⭐⭐⭐⭐ | ⭐（需硬件） |

### 9.2 推荐方案：A（头部追踪）+ E（CSS 视差）组合

**方案 A——头部追踪裸眼 3D（核心方案）**：

- 使用 `MediaPipe Face Mesh` 或 `TensorFlow.js face-landmarks-detection` 追踪用户面部
- 根据面部位置偏移 Three.js 相机的 X/Y 位置（模拟双眼视差）
- 用户左右移动头部时，地球呈现"立体浮出屏幕"的效果
- **无需眼镜、无需特殊屏幕、纯 Web 实现**

```js
// 伪代码：头部追踪裸眼 3D
import { FaceLandmarker } from '@mediapipe/tasks-vision';

class NakedEye3D {
  constructor(threeCamera, threeRenderer) {
    this.camera = threeCamera;
    this.basePosition = threeCamera.position.clone();
    this.faceLandmarker = FaceLandmarker.createForStreaming(/* ... */);
    this.video = document.createElement('video');
    navigator.mediaDevices.getUserMedia({ video: true })
      .then(stream => this.video.srcObject = stream);
  }

  // 每帧根据面部位置调整相机
  update() {
    const result = this.faceLandmarker.detectForVideo(this.video, performance.now());
    if (result.faceLandmarks.length > 0) {
      const nose = result.faceLandmarks[0][1]; // 鼻尖关键点
      // 将面部偏移映射为相机偏移（归一化坐标 → 相机位移）
      const offsetX = (nose.x - 0.5) * 2;  // -1 ~ 1
      const offsetY = (nose.y - 0.5) * 2;
      this.camera.position.x = this.basePosition.x + offsetX * 0.5;
      this.camera.position.y = this.basePosition.y - offsetY * 0.5;
      this.camera.lookAt(0, 0, 0); // 始终看向地球中心
    }
  }

  toggle(enabled) {
    this.enabled = enabled;
    // 关闭时恢复默认相机位置
    if (!enabled) this.camera.position.copy(this.basePosition);
  }
}
```

**方案 E——CSS 视差层（辅助/降级方案）**：

- 在地球 Canvas 上方叠加多层半透明 UI 元素（云层、星空、信息卡片）
- 根据鼠标移动/设备方向传感器调整各层 `translate3d` 偏移量
- 近层偏移大、远层偏移小，产生视差纵深感
- 可作为无摄像头时的降级方案

```js
// 伪代码：CSS 视差裸眼 3D（降级方案）
class CSSParallax3D {
  constructor(layers) {
    // layers: [{ el, depth }]  depth 越大偏移越大
    this.layers = layers;
    window.addEventListener('mousemove', e => this.onMove(e));
    window.addEventListener('deviceorientation', e => this.onTilt(e));
  }

  onMove(e) {
    const x = (e.clientX / window.innerWidth - 0.5) * 2;   // -1 ~ 1
    const y = (e.clientY / window.innerHeight - 0.5) * 2;
    this.layers.forEach(({ el, depth }) => {
      el.style.transform = `translate3d(${x * depth}px, ${y * depth}px, 0)`;
    });
  }

  onTilt(e) {
    // 移动端陀螺仪
    const x = (e.gamma || 0) / 45;  // 左右倾斜
    const y = (e.beta || 0) / 45;   // 前后倾斜
    this.layers.forEach(({ el, depth }) => {
      el.style.transform = `translate3d(${x * depth}px, ${y * depth}px, 0)`;
    });
  }
}
```

### 10.2 前端——ASR 语音识别替换 Web Speech API

```js
// volc-asr.js —— 替换现有 Web Speech API
class VolcASR {
  constructor() {
    this.ws = null;
    this.recognizing = false;
    this.onResult = null;  // 回调：识别文本
  }

  async start() {
    // 连接后端中转 WebSocket（后端持有火山 Key）
    this.ws = new WebSocket('ws://localhost:8080');
    this.ws.onmessage = (e) => {
      const data = JSON.parse(e.data);
      if (data.text) this.onResult?.(data.text, data.isFinal);
    };

    // 获取麦克风音频流
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    const audioCtx = new AudioContext({ sampleRate: 16000 });
    const source = audioCtx.createMediaStreamSource(stream);
    const processor = audioCtx.createScriptProcessor(4096, 1, 1);

    source.connect(processor);
    processor.onaudioprocess = (e) => {
      if (!this.recognizing) return;
      const pcm = e.inputBuffer.getChannelData(0);
      // 将 PCM 音频流发送到后端 → 火山引擎 ASR
      this.ws.send(pcm.buffer);
    };
    this.recognizing = true;
  }

  stop() {
    this.recognizing = false;
    this.ws?.close();
  }
}

// 使用示例：替换 earth.html 中的 SpeechRecognition
const asr = new VolcASR();
asr.onResult = (text, isFinal) => {
  if (isFinal) handleVoiceCommand(text); // "飞到北京" → 地球操作
};
```

### 10.3 前端——豆包 LLM + Function Calling 控制地球

```js
// geo-assistant.js —— AI 地理助教
class GeoAssistant {
  constructor() {
    this.messages = [];
  }

  async ask(userText) {
    this.messages.push({ role: 'user', content: userText });

    const resp = await fetch('/api/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ messages: this.messages })
    });

    // 读取 SSE 流
    const reader = resp.body.getReader();
    let assistantText = '';
    let toolCall = null;

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      const chunk = new TextDecoder().decode(value);
      // 解析 SSE：提取文本 + function call
      const parsed = this.parseSSE(chunk);
      if (parsed.text) {
        assistantText += parsed.text;
        this.updateUI(assistantText);  // 实时显示回答
      }
      if (parsed.toolCall) toolCall = parsed.toolCall;
    }

    // 执行 Function Calling → 操作地球
    if (toolCall) {
      this.executeEarthCommand(toolCall);  // 如 flyTo('北京')
    }

    this.messages.push({ role: 'assistant', content: assistantText });
    return assistantText;
  }

  executeEarthCommand(call) {
    const { action, target } = call.arguments;
    if (action === 'flyTo') earthApp.flyToCity(target);      // 定位城市
    if (action === 'showLayer') earthApp.toggleLayer(target); // 显示气候带等
    if (action === 'setView') earthApp.setViewMode(target);   // 切换2D/3D
  }
}
```

### 10.4 前端——TTS 语音播报

```js
// volc-tts.js —— AI 助教语音播报
class VolcTTS {
  async speak(text) {
    const resp = await fetch('/api/tts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        text,
        voice_type: 'BV001_streaming',  // 预置音色
        speed: 1.0,
        encoding: 'mp3',
      })
    });

    // 流式播放音频
    const audioCtx = new AudioContext();
    const source = audioCtx.createBufferSource();
    source.connect(audioCtx.destination);

    const reader = resp.body.getReader();
    const audioChunks = [];
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      audioChunks.push(value);
    }

    const audioBuffer = await audioCtx.decodeAudioData(
      await new Blob(audioChunks).arrayBuffer()
    );
    source.buffer = audioBuffer;
    source.start();
  }
}
```

## 十一、风险与注意事项

### 11.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **API Key 泄露** | 严重——火山引擎计费 Key 被盗用 | **必须后端中转**，前端永远不接触 Key |
| **需联网** | 校园断网时语音功能不可用 | 保留 Web Speech API 作为离线降级 |
| **摄像头权限** | 头部追踪裸眼 3D 需摄像头授权 | 提供 CSS 视差降级方案（无需摄像头） |
| **延迟** | ASR + LLM + TTS 链路延迟可能 ~1-2s | 用流式 ASR + 流式 LLM + 流式 TTS 降低首字延迟 |
| **浏览器兼容** | WebSocket / AudioContext 需现代浏览器 | 明确支持 Chrome/Edge/Safari/Firefox 最新版 |

### 11.2 成本风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **TTS 成本占比高** | ~¥4/课（90 次播报） | ① 用 lite 模型 ② 减少 TTS 频率（仅关键回答播报）③ 新客套餐先测试 |
| **超量计费** | 流量突增 | 设置火山引擎控制台用量告警 |
| **免费额度用尽** | 20h ASR / 20h 大模型 ASR | 监控用量，及时购买套餐包 |

### 11.3 合规与隐私

- 学生语音数据会上传至火山引擎服务器，需在隐私政策中告知
- 建议课堂模式下仅教师端开启语音，学生端用文本输入
- 头部追踪摄像头画面仅本地处理（MediaPipe 本地推理），不上传

> 火山引擎对本项目的价值**高度集中于 AI 语音三件套**（ASR 流式识别 + TTS 情感合成 + 豆包 LLM 对话），用它替换现有 Web Speech API 即可实现"AI 语音与地球功能深度交互"——价格极低（doubao-1.5-lite 输入仅 0.3 元/百万 token，单课成本 <¥1）。但**3D 渲染、地图影像、裸眼 3D 均不应依赖火山引擎**（它无相关产品），应分别用 Three.js（现有）、Cesium（已有调研结论）、自研头部追踪方案。所有火山引擎 API **必须通过后端中转**以保护 Key 安全，裸眼 3D 推荐用 MediaPipe 头部追踪 + Three.js 相机偏移实现纯 Web 方案。
